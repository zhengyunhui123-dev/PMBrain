# 中文会话对齐实施

本轮复用现有导入和 Context 能力，不扫描会话目录、不安装 hook、不重建向量。参考本地 GBrain 的 transcripts/codex.ts、grok.ts 和 Schema Pack 路径防护；未整体复制采集架构。

## 使用

- 管理台现有文件附件入口可手动选择 `.jsonl`。Codex 文件必须有 session_meta；Grok 使用原始 `chat_history.jsonl` 文件名和 system 首条记录。不是任意 JSONL 都能导入。
- CLI：`pmbrain import "D:\导出\chat_history.jsonl" --source-id <来源ID> --no-embed`。是否向量化沿用现有配置；示例显式关闭向量化。
- 文件上限 20 MB。损坏 JSON、缺少必要正文、无法识别格式均报错，不把原始 JSON 当作普通知识兜底导入。
- 用户与助手正文保留；系统提示、推理和工具记录、注入提醒不作为正文。只使用源文件明确提供的逐条时间戳；Grok 无时间戳记为缺失。
- 完全相同的原始文件在同一 Source 内去重。追加内容或改变原始字节后是新快照，不覆盖之前快照；不同 Source 独立保存。该方案不进行跨快照语义去重。
- 正文使用引用块展示，避免消息中的角色标题被误识别为另一条发言。原始文件不改写。

## 已实施

- 中文用户/助手标题、发言人/说话人编号、全角冒号兼容；否定、提议、待办原文保护。
- Schema Pack 修改允许中文类型和别名；中文关系原有支持通过回归。包文件路径检查拒绝目录穿越，合法点号/下划线包标识保留。
- 手动会话共享适配、CLI 和管理台附件接入。Context Pack、Delta 和 Source/session 机制沿用，未新增自动采集。
- 千问原生输出救回、DeepSeek 工具调用保护及 reasoning JSON 既有回归通过，不为对齐重写已有修复，不新增国外模型供应商。

## 验证与边界

中文解析与既有解析 74 项通过；Schema Pack、Context 和国产模型定向回归通过；PGLite 验证快照去重、跨 Source 隔离、引用标题保护和原文件保留；CLI 手动入口通过。Postgres 同一行为测试已加入 E2E，本机未配置测试库，明确跳过。没有用用户真实库或真实中文标注题集评估效果，不能报告真实误判率、Recall 或成本提升。

与最初规划的差异：经用户确认，Context 扩展本轮缩为沿用现有机制，原始会话只做手动文件入口。严格词汇白名单未强加到历史知识导入；本轮解决可复现的中文维护不一致和包路径问题。Facts idea 与抽取提示附录留待下一阶段，Source 路径架构及严格分块认证继续暂缓。

GitHub、远程 CI 和安装包由用户处理，本地不执行 build:win。
