## 4. 明确冲突或暂不吸纳

1. **不能直接移植安全分块升级流程。** 上游 safe-chunks 要求 chunker_version 达到 4；import-file 会在事务中删除旧 chunks 后重建并认证，不继承旧上下文向量。它解决隐私残留，但会影响旧资料远程可检索性、向量保留、重算费用和升级等待。PMBrain 必须设计“读取安全检查 + 本地可用性 + 用户明确选择的重建”边界。不能将旧 chunk 直接标安全，也不能自动全库重建。安全目标应吸纳，数据操作不可照搬。
2. **语义结果缓存暂停需要明确体验取舍。** GBrain semanticResultCacheAvailable() 当前直接返回 false，因为缓存结果的全部依赖不能重新授权。PMBrain 的中文文本守卫、Source/参数哈希并不能直接证明已解决所有贡献页面和 holder 的权限变化。建议以安全收紧为先，评估延迟；在证明完整权限重验证前不能恢复该缓存，也不必删除旧缓存数据。
3. **代码检索 Agent 入口不能原样保持开放。** 上游当前对 codeIntelOperations 的读取 handler 要求 ctx.remote === false，Agent 调用被拒绝，因图扩展权限链未完整实现。PMBrain 尚无同等处理。应选择同步收紧，或先补全权限再开放；不能只抄早一版 Source 修复却忽略最新限制。不是删除本地代码检索能力。
4. **默认云模型、默认 Reranker 和云端外发不照搬。** 保留无默认 Embedding、普通模型与向量配置分离、失败不切换向量供应商、balanced 默认不依赖专用 Reranker。
5. **Ambient memory writeback / Memorable 不默认启用。** 上游新增 opt-in、同意检查、hook 和多宿主捕获；PMBrain 暂无同等完整链路。这是可选自动写入/集成项目，必须另行确定采集范围、Source、撤回、TTL、外发同意和 PGLite 锁边界。不能随代码升级自动采集或写入。
6. **Chronicle、本体冲突、Google/Gmail/Calendar 与 loops、SkillOpt、brain-resident skillpack** 仍属独立扩展候选或历史暂缓项。本次没有足够逐项行为证据把它们列为已批准同步；不应为版本追齐引入新数据模型、凭证依赖或自动改 Skill。
7. **跨目录全局 basename 实体合并不采用。** 继续遵守 Source 内优先、default 共享回退和显式跨 Source 链接，避免同名人物/项目串库。
8. **纯文件拆分不作为对齐目标。** 上游 ops、engine 子模块、bootstrap 等布局与 PMBrain 不同。优先移植行为和契约，不为对齐目录结构大拆 CLI/Operation/数据库核心。

与原建议的差异和暂缓：

1. 严格分块认证、历史分块重建不纳入本轮，遵循用户明确选择；不把 NULL receipt 或旧分块伪装为已认证。
