# PMBrain 中文项目知识库 Benchmark

## 真实项目与模型核对

`real.ts` 读取用户预先标注的私有原文快照与问题，不从正式数据库取写权限。题集至少 30 问；每题包含 sourceId、相关页面、预期回答条件及原文逐字证据，标注须在首次评分前冻结。原文 snapshot 的来源和哈希应保留，账号、密钥和无关私密内容需在副本中移除。真实资料和逐题模型输出仅放在 `.codex/` 或 `eval/private/`，不得提交。

```bash
bun eval/pmbrain-zh-project/real.ts --dataset eval/private/real-project.json --config <现有配置.json> --work-dir eval/private/real-project-run
```

配置必须显式提供 embedding_model、embedding_dimensions、chat_model。Runner 只在隔离目录中保存无密钥的向量配置和独立 PGLite；复用生产默认递归分块、title contextual embedding、现有 Gateway、Worker owner 与 hybridSearch。向量真实写入后按实际 model 字段审计。回答和评审保留实际模型、Token、延迟、错误和调用结果，关闭模型回退；使用原生错误，不切换供应商。中断后用同一命令续跑，题集或模型变化必须另用隔离目录。

这一轮采用 balanced、关闭扩展和重排，回答只接收前 8 条检索片段；属于单次检索回答基线。整份资料可能还有未进入上下文的内容，需另验收产品已有的 knowledge_read 继续读取原文链路。引用页命中、原文引句匹配、整段回答事实支持和答案正确分别记录；引句匹配只消除 PDF 软换行，不接受改写或跨 Source 引用。语义支持由评审模型判定，并保留人工复核位置，不能用正确页名代替事实支持。回答与评审使用同一模型，存在相关偏差，自动评分不等于人工验收。未跑完的报告标为 partial，不宣称完整质量门通过；完整质量门失败或存在调用错误时返回非零退出码。

1.4.95 的本地真实项目验证使用 8 份只读资料快照、34 道预标注问题，覆盖多资料、不同表达、事件日期、历史版本、否定、人物分工及无依据拒答。实际使用 Qwen3 Embedding 0.6B（1024 维）和 MiMo V2.6 Flash，34 问均完成，错误为 0；页面 Recall@5 为 1，MRR 为 0.9167，返回引句原文匹配率和已检验 Source 范围准确率为 1，完整语义质量门仍失败。主要失败是片段未覆盖关键句却提前结束作答、同日多版文案混淆和多资料答案不完整。另用产品原生 knowledgeWorkbenchAnswer 核验 5 道关键题，核心结论经人工逐项对原文；实际未触发 knowledge_read，不据此宣称该工具的真实模型续读链路已验收。自动评审曾错误归因人物立场，旧版 abstained 元数据守卫也误判否定回答；保留原始评分和复核记录，末次补充评审超时，未替换模型或以错误评分宣称通过。私有题目和模型原文没有进入仓库，公开摘要为 `results/2026-10-17-1.4.95-real-summary.json`。

1.4.94 复测：现有中文规范化增加确定性主题变体，保留原问句、原始名称、同义表达与最多 4 个词法查询上限。所有变体沿用同一 Source、类型、排除项和时间过滤，继续走原有混合检索；旧缓存由 epoch 14 隔离。

同配置、同语料与同 100 问的结果保存在 `results/2026-10-17-1.4.94-keyword.json`：Recall@5、MRR、首位命中率和已检验的 Source 隔离均为 1，精确名称探针 20/20，错误和缺失均为 0，检索门通过。题目和阈值未改。双引擎回归另测其他名称、引号、中英混合名称、20 页通用干扰、无此项目及时间/类型/排除项。

当前提取范围是常见项目属性和问句形式。该题集每项目只有一页，五类句式重复；100/100 只证明这些固定句式的检索回归通过。多实体、同项目多页、否定条件、无同词改写、真实向量、回答及引用事实支持率仍需独立 holdout 和真实模型验证，`full_quality_gate` 仍为 `not_evaluated`。

这是一套不读取用户知识库的合成评测：两个 Source 中的 20 个项目、100 个固定中文问题，覆盖风险、承诺、日期、金额和决策。同名项目在两个 Source 中有不同正文，查询严格限定 Source。

运行：

```bash
bun run eval:pmbrain-zh-project
```

保存逐题结果：

```bash
bun run eval:pmbrain-zh-project --output .codex/zh-baseline.json
```

本地快速检查可设置 `PMBRAIN_BENCH_LIMIT=10`；默认值始终是完整的 100 问，CI/正式消融不得使用限量模式。

v2 通过现有独立 PGLite owner 调用真实 `hybridSearch`，不按已知答案制造查询向量，也不向问题追加内部编号。默认 `balanced`，未配置向量，关闭查询扩展与重排，不调用生成模型；这是一条实际关键词、标题和关系检索基线。

报告保存版本、基础提交与工作区是否有改动、配置、逐题排名、失败和缺失结果、延迟及实际 `vector_enabled` / `reranker_applied`。独立的 20 条精确项目名探针只用于确认语料与 Source 范围，不混入 100 条完整问句的分数。

未执行回答模型时，`citation_correctness` 为 `null`，不能用首条检索结果代替回答引用。调用方提供真实 `citedSlugs` 时该字段也只表示引用页匹配率，不等于引用事实支持率。Token 为 0 只代表本 runner 没有模型调用。

100 问的检索门要求 Recall@5 ≥0.85、MRR ≥0.70、首位命中率 ≥0.70、已检验的 Source 隔离 100%、无错误和缺失；未通过时返回非零退出码。限量运行始终标记 `partial`。`full_quality_gate` 保持 `not_evaluated`，因为这条合成基线没有覆盖真实用户题集、语义向量、模型回答或事实支持率。不得根据当前排名修改问题来消除失败。

该种子集用于阻止明显回归，不替代真实 PMBrain 私有语料上的人工标注 holdout。扩展算法默认值前，应同时提供合成集和私有 holdout 的消融证据。

2026-10-17 的历史 1.4.93 基线保留于 `results/2026-10-17-1.4.93-keyword.json`。当时精确名称及 Source 探针 20/20 通过，完整中文问句 0/100 命中，检索门失败；完整问句没有返回结果，因此该报告的 Source 隔离通过率为空。原因是当时 PGLite 中文候选只按完整文本及日期变体匹配，未从问句中得到项目主题。1.4.94 使用同一题集复测，结果和剩余边界见上文。
